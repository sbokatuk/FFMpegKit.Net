## What's changed

Binding-pin update. FFmpeg is still `8.1.2`; the cross-platform API is unchanged from `8.1.2.1`, and this release exists to pick up the newest revision of each platform binding:

```
FFmpegKit.Net.<Variant>.Maui        MAUI wiring: UseFFmpegKit()/AddFFmpegKit() + FilePicker/SAF helper
  └─ FFmpegKit.Net.<Variant>        the cross-platform API   (Android, iOS, macOS)
       ├─ FFmpegKit.Net.<Variant>.Android   8.1.2.4 → 8.1.2.5
       ├─ FFmpegKit.Net.<Variant>.iOS       8.1.2.1 → 8.1.2.2
       └─ FFmpegKit.Net.<Variant>.Mac       8.1.2.1 → 8.1.2.2
```

Upgrading is a version bump and nothing else — no API changed in this package, and no consumer code needs editing.

### What the new bindings bring

Most of this only matters if you drop below the cross-platform API to `Ffmpegkit.Droid` / `Ffmpegkit.Ios` / `Ffmpegkit.Mac` directly, which stays fully supported:

- **Android build-time constraint checks.** Apps that reference the Android binding (directly or transitively through this package) now get **`FFMPEGKIT001`** when `SupportedOSPlatformVersion` is below 24, and **`FFMPEGKIT002`** when the build includes 32-bit runtime identifiers (`android-arm`, `android-x86`). FFmpegKit ships no 32-bit native libraries, so both previously failed only at runtime, on the device, as a failure to load `libffmpegkit.so`. They are warnings, each suppressible on its own via `NoWarn`.
- **Nullable annotations** on the hand-written parts of all three bindings — the async wrappers, ergonomics helpers and typed media accessors — so nullable-enabled apps get real annotations on the surface they touch most.
- **`FFmpegKitConfig.DisableLogCallback()` / `DisableStatisticsCallback()`** on all three bindings, replacing the `EnableLogCallback((ILogCallback)null!)` incantation for clearing the global hooks.
- **macOS signing guidance** in the Mac binding's README: how the embedded frameworks are signed as part of the app bundle, what hardened runtime and library validation expect for notarization, and the inside-out rule for custom signing scripts.
- **Supply chain**: the Android binding now verifies every native `.aar` and jar it downloads against a SHA-256 baseline committed in its repository, enforced on every build including CI cache restores.

### Reminder: the API this package adds

Unchanged since `8.1.2.1`, repeated here because it is the reason to use this package rather than a binding directly — one `FFmpegKit`/`FFprobeKit`/`FFmpegKitConfig` surface across Android, iOS and macOS, awaitable with `CancellationToken`, `IProgress<FFmpegProgress>` reporting, typed `MediaInfo` parsed invariant-culture everywhere, the failed command's console `Output` on the result, `EnsureSuccess()` for exception-preferring code, and an injectable `IFFmpegKit` registered by `UseFFmpegKit()` / `AddFFmpegKit()`.
