## What's changed

First release of the cross-platform FFmpegKit packages: **one `FFmpegKit`/`FFprobeKit` API over the Android, iOS and macOS bindings**, plus a thin .NET MAUI companion package — instead of every app writing its own adapter over `Ffmpegkit.Droid`, `Ffmpegkit.Ios` and `Ffmpegkit.Mac` by hand.

> **Package versions are `<ffmpeg version>.<binding revision>`.** `8.1.2.1` is FFmpeg `8.1.2`, revision `1`. The fourth component belongs to this repository and increments when the cross-platform layer changes while FFmpeg stays put. The [Android](https://github.com/sbokatuk/FFmpegKit.Android), [iOS](https://github.com/sbokatuk/FFmpegKit.iOS) and [Mac](https://github.com/sbokatuk/FFmpegKit.Mac) bindings use the same scheme; their revisions advance independently of this one.

The package chain, per variant (`Audio`, `Full`, `FullGpl`, `Https`, `HttpsGpl`, `Min`, `MinGpl`, `Video`):

```
FFmpegKit.Net.<Variant>.Maui        MAUI app-builder wiring + FilePicker/SAF helper (Android, iOS)
  └─ FFmpegKit.Net.<Variant>        the cross-platform API   (Android, iOS, macOS)
       ├─ FFmpegKit.Net.<Variant>.Android   8.1.2.4   (net8.0-android34.0 / net9.0-android35.0 / net10.0-android36.0)
       ├─ FFmpegKit.Net.<Variant>.iOS       8.1.2.1   (net8.0-ios18.0 / net9.0-ios18.0 / net10.0-ios26.0)
       └─ FFmpegKit.Net.<Variant>.Mac       8.1.2.1   (net8.0-macos14.0 / net9.0-macos15.0 / net10.0-macos26.0)
```

Each target framework depends on exactly one platform binding, pinned to an exact version. Plain .NET for Android / iOS / macOS apps reference `FFmpegKit.Net.<Variant>` directly; only MAUI apps need the `.Maui` package on top.

## ⚠️ Superseded prereleases and breaking notes

**The `6.0.0.1-beta1` prereleases under these ids are superseded.** They came from an earlier iteration of this repository — per-platform Xamarin-style bindings of FFmpeg 6.0 under a numbering scheme that no longer applies. `8.1.2.1` is a different kind of package (a cross-platform API layer over the separately published bindings) built on FFmpeg **8.1.2**; expect upstream FFmpeg behaviour changes across two major versions. nuget.org does not allow prereleases to be deleted, so the betas remain resolvable by exact version, but nothing should reference them.

**The namespace is `Ffmpegkit.Net`, deliberately not `FFmpegKit.*`.** A namespace rooted at `FFmpegKit` containing a type also called `FFmpegKit` would make `FFmpegKit.ExecuteAsync(...)` resolve the namespace instead of the class and fail to compile. Corollary: if your app's own root namespace starts with `FFmpegKit`, qualify calls as `Ffmpegkit.Net.FFmpegKit.ExecuteAsync(...)` — the sample shows this.

**Mac Catalyst is not supported** — no native FFmpegKit Catalyst slice is published anywhere. macOS support is the *client* package's `net*-macos` target frameworks (AppKit / plain .NET for macOS apps); `FFmpegKit.Net.Maui` stays Android + iOS, since MAUI's "Mac" is Catalyst.

## The API

One code path on every platform, no platform branches:

- **`FFmpegKit.ExecuteAsync(command)`** / **`ExecuteWithArgumentsAsync(args)`** — awaitable, with a `CancellationToken` wired to the running session's own cancellation. A failing command completes with `Failed` rather than throwing; a cancelled one with `Cancelled`.
- **`FFmpegKit.ExecuteAsync(command, IProgress<FFmpegProgress>, totalDuration)`** — typed progress samples (position, percent, size, bitrate, speed, ETA) with clamping and null-handling applied identically on all platforms.
- **`FFprobeKit.GetMediaInformationAsync(path)`** — typed `MediaInfo`/`StreamInfo` records (duration, dimensions, codecs, frame rates, tags), parsed **invariant-culture** everywhere: FFprobe reports numbers as strings, and `double.Parse("12.345000")` reads as twelve million under a de-DE locale.
- **`FFmpegKitConfig`** — log level get/set as a plain C# enum, a log-line delegate, session-history clearing.
- **MAUI**: `builder.UseFFmpegKit()` and `FFmpegKitMaui.GetInputArgumentAsync(FileResult)`, which resolves Android `content://` URIs through the Storage Access Framework and passes paths straight through on iOS.

The platform bindings underneath expose FFmpegKit's full native API; anything not covered by the cross-platform surface is reachable through them directly.

## Licensing

The C# in this repository is MIT, but each package declares `MIT AND LGPL-3.0-only` (or `AND GPL-3.0-only` for the `-Gpl` variants) — the licence of the native FFmpeg build it transitively pulls in, which is what your app actually ships. The applicable texts are packed under `licenses/` in every package. **If your app is closed-source, use a non-GPL variant.**
